# GW170817 revision run — mlgw_bns_jax (GPU) vs bilby TEOBResumSPA (LDG)

Referee comments addressed: **1b** (JSD against a bilby/dynesty run with the baseline approximant),
**1c** (Λ ≤ 1200 and other narrow priors → LVK-standard priors), **1d** (PSD, calibration), **1e**
(frequency cutoffs), **6** (run-time breakdown, bilby RB timing).

Both codes analyse **byte-identical frozen data** (sha256-checked), with the same priors, the same
likelihood (relative binning, phase marginalised; tc marginalised in gwjax and sampled over an
equally wide window in bilby) and the same sampler settings (acceptance-walk NS, nlive 1000,
naccept 60, maxmcmc 5000, dlogz 0.1).

## Findings while building this kit

1. **Data-conditioning bug in the published run (fixed in `gwgpu_jax`, Nov 2026).** The notebook
   passed `bandpass=(23, 2048)` to `attach_data_to_network`, which applied gwpy's default
   `highpass(23)`: a Chebyshev-I IIR with 2 dB passband ripple, run with filtfilt. Its amplitude
   response ripples between 0.63 and 1.0 over ~23–400 Hz (0.66 at 30, 60, 100 Hz; 0.85 at 200 Hz).
   Neither the PSD nor the templates see that filter, so the signal in the data was rescaled: the
   published data whitened to 0.5–0.6 (instead of 1) between 40 and 200 Hz, in H1, L1 and V1 alike.
   An in-band amplitude loss of ~0.75 maps onto a ~1/0.75 larger distance, consistent with the
   published d_L ≈ 50 Mpc vs ~40 Mpc (to be confirmed by this rerun). `_flat_band_filter` (zero-phase Butterworth, flat to 0.15%
   in band, `tests/test_band_filter.py`) replaces it; this kit applies no filter at all (bilby/LVK
   convention). GW150914 is not affected (`attach_event_to_network` defaults to `bandpass=None`).
2. **PSD (comment 1d).** The LVK released the GWTC-1 GW170817 PSDs (BayesWave on-source, DCC
   LIGO-P1900011) on exactly our 1/128 Hz grid; they whiten this data to 0.96–1.08 in every band up to
   1600 Hz. The published Welch PSD (1024 s, 128 s segments, 15 averages, contains the event) is ~7% low
   (whitened power 1.06–1.10; V1 1.1–1.3). `PSD_MODE = "gwtc1"` is the default; `"welch"` reproduces
   the published PSD for the impact comparison.
3. **Upper cutoff (comment 1e).** The GWOSC 4 kHz BWCLEANED files carry the anti-alias low-pass of
   the 16→4 kHz decimation: whitened power 0.79 at 1650–1700 Hz, 0.36 at 1700–1750 Hz, ~0 above
   1800 Hz, identical in all detectors. It filters the signal too, so GWTC-1's 2048 Hz cannot be used
   with these files; 23–1500 Hz (as published) is kept and now justified.
4. **Reference waveform.** mlgw_bns's default model is trained on TEOBResumS in its SPA Fourier-domain
   mode (`EOBRunPy`, `domain = 1`), i.e. TEOBResumSPA — the BNS baseline the referee names. It is not a
   LALSimulation approximant; `teobresumspa_source.py` calls the `teobresums` package. At a GW170817-like
   point: mlgw_bns_jax vs TEOBResumSPA overlap 0.999999 (hp and hx with the same time/phase shift),
   TEOBResumSPA vs LAL IMRPhenomD_NRTidalv2 0.99985, hx/hp and |hp| identical to LAL conventions.
   The template time origins differ by a fraction of a ms; bilby centres its geocent_time window at
   (TEOB likelihood peak − `mlgw_tc_peak_offset_s` from `metadata.json`), i.e. where gwjax's TC0 ± 1 ms
   window sits relative to its own peak.
5. **bilby relative binning.** bilby's default `epsilon = 0.5` (62 bins) is off by 1–6 in ln L for
   modest offsets and by ~90 at Λ₁ = 2000; `epsilon = 0.01` (3092 bins) gives |Δln L| ≤ 0.005 near the
   peak (0.05 at Λ = 1500/2500). The TEOB ODE dominates the cost (≈ 40–70 ms per call on one core,
   independent of the bin count); the full likelihood costs ≈ 0.27 s. Network SNR at the paper's
   fiducial point: 32.2 (TEOBResumSPA, GWTC-1 PSD; GWTC-1 quotes 32.4).

## Priors (both codes)

| | published | revision |
|---|---|---|
| M_c (detector frame) | U(1.19, 1.20) | uniform in components, [1.18, 1.21] |
| q = m2/m1 | U(0.68, 1) | uniform in components, [0.34, 1] (surrogate: m1/m2 ≤ 3) |
| χ₁, χ₂ | U(−0.15, 0.15) | AlignedSpin \|a\| ≤ 0.05 (GWTC-1 low spin); `--spin-prior high`: 0.5 (surrogate limit) |
| Λ₁, Λ₂ | U(5, 1200) | U(5, 5000) |
| d_L | ∝ d², [1, 50] Mpc | ∝ d², [1, 75] Mpc |
| ι, ra, dec, ψ | sin, U, cos, U | same |
| tc / φ_c | marginalised | gwjax: marginalised (TC0 ± 1 ms, 800 pts / analytic); bilby: geocent_time sampled over 2 ms, phase analytic |

## How to run

1. **Freeze** (any machine with `gwgpu_jax[data]`; already done for both modes on the author's laptop):

       python freeze_gw170817_data.py                   # data_gwtc1/
       python freeze_gw170817_data.py --psd-mode welch  # data_welch/

   The `.npy` arrays (~19 MB per mode) are not committed; `metadata.json` (checksums) is.
2. **GPU (Colab):** copy `data_gwtc1/` (and `data_welch/`) to `MyDrive/gwjax_referee/gw170817_data/`,
   open the notebook, run all. Output: `MyDrive/gwjax_referee/gw170817_mlgw_bns_lvkpriors/<timestamp>_<psd>_<spin>spin/`.
3. **CPU (LDG):**

       rsync -a data_gwtc1 <ldg>:~/GWgpu-jax/examples/referee_response/gw170817_mlgw_bns/
       ssh <ldg>; cd ~/GWgpu-jax/examples/referee_response/gw170817_mlgw_bns
       bash setup_ldg_env.sh                 # once
       condor_submit run_bilby_gw170817.sub  # 32 cores (~10 h); resubmit to resume

4. **Compare:** `bash compare_gwjax_bilby.sh <Drive RUN_DIR> <bilby_..._result.json>`.

Not changed (stated in the paper): (2,2) mode only, aligned spins, no calibration marginalisation,
Euclidean d² distance prior.
